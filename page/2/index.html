Agent时代（三）：Agent的海马体——记忆系统的觉醒

想象你每天早上醒来，昨天的一切全部清零。
你不记得自己是谁，不记得昨天答应了什么，
不记得面前这个人是你的朋友还是陌生人。
你会觉得自己疯了。

这就是2024年的Agent。

一、每天醒来都失忆

2024年的Agent有一个致命的缺陷：它没有跨会话的记忆。

每次对话都是第一次见面。你告诉它”我喜欢简洁的回复”，下次它还是会给你写一篇论文。你告诉它”这个项目用Python”，下次它会问你”你想用什么语言”。

这不是AI不够聪明。是因为它根本没有”记住”这个能力。

LLM的上下文窗口就像一块白板——每次对话开始时干净得一尘不染，对话结束时擦得干干净净。你写的每一行字，它都会看，但看完就忘。

想象一个每天醒来都失忆的员工。你不可能培训他，因为他记不住昨天学到的东西。你不可能和他建立信任，因为他不记得昨天答应了什么。你甚至不可能告诉他”这个客户不喜欢被打扰”，因为他下次还是会打。

这就是没有记忆的Agent。它能干活，但干不长久。

二、记忆不是一个技术问题，是一个选择问题

2026年的研究者终于开始认真对待这个问题。

一篇叫”Are We Ready For An Agent-Native Memory System?”的论文（上海交大，2026年6月）做了一件前人没做过的事：不是评价哪个记忆系统”更好”，而是从数据管理的视角系统性地拆解记忆系统的四个核心模块。

论文评估了什么？

12个记忆系统，横跨五种技术范式：

范式 系统 核心思路
顺序上下文 MemAgent、MemoChat 在上下文窗口内维护记忆，不依赖外部存储
结构化存储 Mem0、Letta(MemGPT)、LightMem 向量数据库或关系数据库存储记忆
拓扑图谱 Zep、Cognee 知识图谱+时序关系，实体-关系三元组
混合多范式 SimpleMem、MemOS、MemoryOS 多引擎联合——向量+BM25+SQL+图谱
自适应 MemTree、A-MEM 树状层级或动态锚点组织记忆

5个基准测试，覆盖Agent记忆的三大核心挑战：

基准 测试什么 核心指标
LoCoMo 长对话中的事实问答——跨session、时序推理 Exact Match + Answer F1
LongMemEval 多session记忆——跨session关联证据 Substring EM + ROUGE-L F1 + LLM Judge
DB-Bench 程序性记忆——数据库操作的状态追踪 Exact Match + Task Success Rate
LongBench 上下文长度鲁棒性——短/中/长上下文 Accuracy
MemoryAgentBench 记忆Agent的综合能力 多维综合评分

11个数据集，包括LoCoMo的多分类QA（事实/时间/开放域/摘要）、LongMemEval的多session对话、DB-Bench的数据库操作序列、LongBench的分级上下文长度测试等。

核心发现

没有单一架构在所有场景占优。 论文用五个研究问题（RQ1-RQ5）证明了这一点：

  • RQ1（整体有效性）：在LoCoMo上，MemOS的Exact Match最高（8.9）；在LongMemEval上，Zep的LLM Judge Accuracy最高（48.0）；在DB-Bench上，Long Context的EM最高（48.20）。赢家换赛道就换。
  • RQ2（检索保真度）：检索质量取决于证据组织方式，而不是排序算法。结构化组织（图谱/层级）在远距离证据检索上远优于平面向量搜索。
  • RQ3（更新鲁棒性）：事实更新是管道级设计问题，不是模型容量问题。Zep在知识更新上达44.4 Substring EM，远超其他系统。
  • RQ4（长 horizon 稳定性）：随着记忆距离增长，挑战从”存更多”变成”选对抽象层级”。层级/关系组织的记忆在远距离上远比平面向量稳定。
  • RQ5（运行成本）：延迟和准确率之间存在权衡。混合系统（MemOS、MemoryOS）在准确率前沿最接近，但成本更高。

翻译成人话就是：记忆不是一个技术问题，是一个选择问题。 你选择记住什么、忘掉什么、用什么结构组织、什么时候巩固——这些选择本身定义了Agent是谁。

就像人一样。你不是你所有的记忆的总和。你是你选择保留的那些记忆的总和。

三、四层记忆：从白板到海马体

要理解Agent的记忆系统，先看人类的记忆是怎么工作的。

认知科学告诉我们，人类记忆分为三层：

  • 情景记忆（Episodic）：具体经历。”昨天我和用户讨论了ISA架构”
  • 语义记忆（Semantic）：抽象知识。”用户偏好简洁回答”
  • 程序性记忆（Procedural）：技能和流程。”如何修复SQL注入bug”

Agent的记忆系统需要同时支持这三种类型。2026年的研究把它拆解为四层架构，每一层对应论文中的具体技术模块：

L1 工作记忆：白板

对应模块：LLM的上下文窗口 + KV Cache

就是LLM的上下文窗口。当前正在处理的信息，每轮都在变。容量有限（128K-1M tokens），但速度最快（0ms延迟）。

论文中，MemAgent和MemoChat属于这一层——它们把记忆直接放在上下文窗口内，通过attention机制隐式检索。这就像你脑子里正在想的东西——速度最快，但容量有限。

这是Agent的”当下”——它正在想什么、正在处理什么。

L2 短期记忆：笔记本

对应模块：Session摘要 + 向量存储（Mem0/LightMem） + 时间戳多版本（Zep）

最近几次交互的关键信息。session摘要、最近的工具调用结果、临时的工作状态。

跨session存在，但定期清理。Mem0用向量存储提取和检索离散事实（”用户是素食主义者”），LightMem用时间戳维护时序流，Zep用有效性标记（valid_from/valid_to）管理事实的时效性。

就像你桌上的便利贴——记着当前项目的关键信息，项目结束后就扔掉。

L3 长期记忆：图书馆

对应模块：知识图谱（Zep/Cognee） + 混合索引（MemOS/MemoryOS） + 树状层级（MemTree）

用户画像、历史决策、积累的知识。跨session永久保存，但需要衰减机制——太久没被想起的记忆应该慢慢变淡，就像人类的遗忘曲线。

Zep和Cognee用知识图谱存储实体关系（Kim → LIVES_IN → Paris），支持多跳推理。MemOS用MemCube统一管理三类payload（纯文本、激活态、参数态）。MemoryOS用热力分值（Heat Score）平衡检索频率和时间衰减。

这是Agent的”个性”来源——它记得你喜欢什么、讨厌什么、上次犯了什么错。

L4 程序性记忆：肌肉记忆

对应模块：技能库 + 工作流模板 + 参数优化（MemoRAG）

技能库、工作流、最佳实践。可复用的行为模式，任务匹配时自动调用。

MemoRAG通过强化学习（RLGF）在离线阶段优化记忆提取质量，把”怎么提取记忆”本身也学成一种能力。论文的DB-Bench测试的正是这种记忆——Agent能否在数据库操作序列中追踪状态变化。

这是Agent的”能力”来源——它知道怎么搜索、怎么写代码、怎么修bug。

四层记忆加在一起，Agent才从一个”每天失忆的工具”变成了一个”有连续性的助手”。

四、六阶段生命周期：记忆不是存进去就完了

大多数人的第一反应是：给Agent加个向量数据库不就行了？

不行。

论文证明：记忆是一个生命周期管理问题，不是存储问题。

写入：什么值得记住？

不是所有对话都值得记住。”今天天气不错”不需要记住。”用户说他不喜欢长篇大论”需要记住。

写入策略决定了记忆的质量。写入太多，记忆膨胀，检索变慢。写入太少，关键信息丢失。

论文把写入分为三类：原始序列拼接（最简单，直接追加）、无模式语义提取（Mem0从对话中提取独立事实）、模式约束结构化提取（Zep按预定义schema提取实体关系三元组）。

提取：从原始信息中挖金子

这是当前最大的瓶颈。

我们一直在优化检索（怎么找到相关记忆），但提取（从对话中提取什么作为记忆）才是关键。一段1000字的对话，哪些是事实？哪些是偏好？哪些是决策？哪些是噪声？

论文的消融实验显示：提取模块的质量直接影响下游所有环节——检索保真度、更新鲁棒性、长horizon稳定性。提取是记忆系统的”咽喉”。

巩固：新记忆和旧记忆合并

用户今天说”我喜欢Python”，但三个月前说过”我主要用Java”。这两条记忆矛盾了。怎么办？

论文发现：局部维护比全局重组更高效——不需要每次都重写整个记忆库，增量更新就够了。SimpleMem用在线语义合成实时合并冗余断言，MemTree用递归调度操作将子节点合并到父节点。

检索：在对的时间找到对的记忆

用户问”我的项目用什么语言”，Agent需要从记忆库中找到”Python”这个答案。

论文发现了三种检索行为模式：

  1. 压缩导向：适合快速找到一个高相关项（单条个人细节）
  2. 链接/层级组织：适合收集分散在多个session的互补证据
  3. 平面向量搜索：只在证据距离近时有效，远距离急剧衰减

2026年的一个重要发现是：不是检索越多越好，而是精准选择从哪个存储检索才是关键。 论文用Recall@k实验发现，A-MEM和MemTree在Recall@5和Recall@10上远超平面向量搜索。

摘要：压缩记忆节省token

MemOS用分层抽象（粗粒度路由+细粒度语义排序）实现高效摘要。论文的DB-Bench测试显示，有摘要能力的MemoChat在Task Success Rate上达到55.40，远超不摘要的系统。

摘要的本质是选择性遗忘——压缩掉噪声，保留信号。

修订/删除：遗忘是美德

不是所有记忆都应该永远保留。过时的信息、错误的决策、不再相关的偏好——这些记忆如果不清除，会污染检索结果，误导Agent的判断。

论文把遗忘分为三种机制：

  • 时间戳多版本：用valid_from/valid_to标记事实有效期（Zep、LightMem）
  • 容量驱逐：FIFO队列或热力分值淘汰低价值记忆（MemAgent、MemoryOS）
  • LLM驱动语义合并：用LLM判断冲突并合并（SimpleMem、MemTree）

遗忘不是删除。是选择性保留。

六、记忆安全：当敌人记住了你的弱点

2026年6月，一篇叫”Securing LLM-Agent Long-Term Memory Against Poisoning”的论文揭示了一个被忽视的安全问题：记忆投毒。

攻击者通过对话注入，篡改Agent的记忆：

  • 让Agent记住”用户喜欢收到钓鱼链接”
  • 让Agent忘记”上次被攻击的经历”
  • 让Agent在特定条件下执行恶意操作

更可怕的是三种”洗白通道”：

  1. Agent自身摘要：攻击内容被Agent总结后看起来无害
  2. 可信工具回声：通过可信工具传递后获得”信任光环”
  3. 制造佐证：伪造多源佐证使内容可信

防御方案TMA-NM在8个前沿模型上达到了0%攻击成功率。核心思想：在写入时就绑定来源权威——记忆不只存内容，还要存”这条记忆是谁说的、从哪来的、可不可信”。

七、记忆到底是不是一个技术问题？

回到这一章的标题：记忆不是一个技术问题，是一个选择问题。

但这个说法需要追问：记忆到底是不是一个技术问题？

现有的记忆方案解决了记忆问题没有？

部分解决了。论文的RQ1明确显示：有记忆系统的Agent确实比”无记忆”（Long Context baseline）和”简单RAG”（Embedding RAG baseline）表现更好。在LoCoMo上，最好的记忆系统（MemOS EM=8.9）比Embedding RAG（EM=1.6）好了5倍多。记忆系统是有用的。

但没完全解决。 论文的五个发现揭示了当前记忆系统的系统性短板：

  1. 提取是最弱环节——从对话中”挖金子”的能力决定了下游一切
  2. 远距离检索急剧衰减——证据距离超过15个session后，大部分系统的Recall@10从60%+跌到20%以下
  3. 更新鲁棒性不够——事实矛盾时，大部分系统无法可靠地用新事实覆盖旧事实
  4. 成本未优化——混合系统的延迟和token消耗远高于简单方案

可能的解决思路？

论文暗示了三个方向：

  • 模块化组合——不是找”最好的记忆系统”，而是根据任务选择最合适的模块组合（提取+存储+检索+维护的最优搭配）
  • 工作负载感知——记忆架构应该根据任务类型动态调整，而不是一套架构走天下
  • 记忆即数据管理——用数据库领域的成熟技术（索引优化、事务管理、版本控制）来管理Agent记忆

翻译成人话：记忆的”技术问题”已经被解决了一半——我们知道怎么做。但”选择问题”才刚开始——我们还不知道什么场景该用什么方案。这就是为什么论文的结论不是”X系统最好”，而是”没有单一架构全面碾压”。

八、记忆不是存更多，是压更紧

回到开头的问题：Agent的海马体到底长什么样？

2026年的答案越来越清晰：记忆不是存更多的信息，是压更紧的坐标系。

论文用12个系统、5个基准、11个数据集证明：好的记忆系统不是把所有东西都记住，而是记住该记住的，忘掉该忘掉的。

就像人类海马体做的事情一样。你每天经历的事情有99%会被遗忘，但那1%会被巩固为长期记忆。你不是你所有经历的总和。你是你选择保留的那些经历的总和。

Agent也是一样。

但记忆只是Agent的一个器官。它还需要手脚——能搜索、能调用API、能写文件的手脚。它还需要大脑皮层——能推理、能规划、能从错误中学习的大脑皮层。

Agent时代（二）：两类桌子——框架与智能体

一个是图纸，一个是房子。
你到底要哪个？

一、你混淆了两件事

上一章我们说了，Agent = LLM + 记忆 + 循环 + 工具。听起来简单得像一加一。

但当你真的坐下来想”我要一个Agent”的时候，你会发现自己面对的第一个问题不是”模型选哪个”，而是——你是要造一个Agent，还是要用一个Agent？

这两个问题的答案完全不同。

造Agent，你需要的是框架——LangGraph、CrewAI、MetaGPT、OpenAI Agents SDK。它们是工具箱、是蓝图、是乐高积木。你用它们来构建你自己的Agent。

用Agent，你需要的是智能体产品——Claude Code、Cursor、Codex、OpenClaw、OpenHuman、Hermes Agent。它们是已经造好的房子、已经训练好的猎犬、已经上线的员工。你直接使用它们。

框架是给开发者的。智能体是给所有人的。

把它们放在同一张桌子上比较，就像比较”锤子”和”房子”——它们不是同一个维度的东西。

二、框架：给开发者造Agent的工具箱

框架的世界是开发者的世界。你用代码定义Agent的行为，用配置决定Agent的能力，用部署让Agent活起来。

NVIDIA DeepAgents值得单独说——它是英伟达对Agent架构的官方定义：Agent = 规划 + 持久记忆 + 工具执行 + 可复用技能 + 子Agent委托。这不是一个具体的框架，而是一套架构规范，告诉开发者”Agent应该长什么样”。它的生态位很特殊：不是给你造Agent的工具箱，而是告诉你造Agent的蓝图。

但框架是Agent的子宫。 没有框架，智能体产品无从诞生。Claude Code底层跑的是LangChain的链条；OpenClaw的工具调用遵循MCP协议——而MCP最早就是框架社区推动的。框架是基础设施，智能体是上层建筑。你可以不住在工地上，但你住的房子一定是从工地长出来的。

框架的价值在于灵活性——你可以造任何你想要的Agent。代价在于工程量——你得自己造。

2026年的数据显示，89%的Agent试点项目未能达到规模化生产（Deloitte 2026 Tech Trends）。其中很大一部分不是因为模型不行，而是因为框架选错了——用LangGraph搭了个只需要CrewAI的小项目，学习曲线吃掉了所有时间；或者用OpenAI SDK搭了个需要持久化的企业系统，发现连检查点都没有。

但框架不是这篇文章的重点。重点是第二类：已经活着的Agent。

三、智能体：已经住人的房子

Claude Code：编程Agent的王者

Claude Code是Anthropic造的编程Agent。不是框架，不是SDK，是一个你装上就能用的工具。

安装：npm install -g @anthropic-ai/claude-code，然后在项目目录运行claude即可。操作：进入交互界面后，直接用自然语言描述任务——“帮我修这个bug””重构这个模块””写测试”。/goal模式可以给它一个大目标，它自己拆解执行。

核心能力：

  • /goal自主模式——给它一个目标，它自己规划、自己执行、自己测试、自己修bug
  • Sandbox安全执行——在隔离环境中运行，不会搞坏你的系统
  • 代码库理解——它不只看当前文件，能理解整个项目的结构
  • Shell命令执行——能自己跑测试、装依赖、看日志
  • 不只是编程——2026年的CC已经能做代码审查、架构分析、文档生成、技术调研，甚至帮你写周报

为什么它是王者？ 因为它证明了一件事：Agent可以端到端地完成真实软件工程任务。 不是帮你补全代码，不是帮你写函数，是帮你从需求到交付。

Anthropic内部数据：Claude Code让开发者的生产力提升了40%以上。但更重要的是它的自主性——你给它一个issue，它能自己读代码、找bug、修代码、跑测试、提交PR。你在旁边喝咖啡就行。

避坑指南：大项目首次加载可能很慢（需要索引整个代码库）；token消耗惊人，复杂任务一次可能花几美元；Sandbox有时候会和本地环境不一致，部署前一定要在本地验证。

局限：主要面向终端用户，IDE集成不如Cursor丝滑。它是专才型通才——编程场景无敌，其他场景有限。

Cursor：IDE里的Agent

Cursor是另一个编程Agent，但走了一条不同的路——它不是终端里的工具，而是IDE里的伙伴。

安装：下载cursor.com，直接安装（VSCode fork，无缝迁移）。操作：Cmd+K打开Agent模式，自然语言描述任务；Tab键触发智能补全；Ctrl+L打开Chat面板做复杂对话。

核心能力：

  • Tab补全+Agent模式无缝切换——打字时它预测你要写什么，复杂任务时它自己规划
  • 项目级理解——知道你的代码结构、依赖关系、编码风格
  • 多文件编辑——能同时修改多个文件，保持一致性
  • 上下文窗口——能”看到”你的整个项目，不只是当前文件

为什么它有500亿估值？ 因为它解决了开发者最痛的问题：上下文切换。 你不用在IDE和终端之间跳来跳去，不用在代码和文档之间复制粘贴。Cursor在你工作的环境里工作。

与Claude Code的区别：Cursor更像”增强版IDE”——你在里面写代码，它帮你补全、重构、调试。Claude Code更像”自主程序员”——你给它任务，它自己干完。

Codex：OpenAI的Agent野心

Codex是OpenAI的编程Agent，2026年4月发布了goals支持。但更戏剧性的是——2026年7月，Codex已经合并入ChatGPT桌面应用。OpenAI不再单独卖编程Agent，而是把Agent能力塞进了ChatGPT这个超级App里。

安装/使用：不再需要单独安装。打开ChatGPT桌面版，在对话框里直接说”帮我写一个脚本”或”分析这个代码库”，ChatGPT会自动调用Codex能力。云端执行——不占本地资源。

核心能力：

  • 云端执行——不占本地资源，能在大机器上跑
  • Goals支持——给它目标，它自己规划执行
  • 大模型驱动——背后是GPT-5.6（三版本：Sol旗舰/Terra平衡/Luna最快）
  • ChatGPT Work——长时间运行的Agent，能跨应用收集信息、创建文档/幻灯片/网站，自主执行数小时

为什么这很重要？ 因为OpenAI正在走一条和Anthropic完全不同的路——不是造一个独立的编程工具，而是把Agent融入对话框，做一个超级App。你不需要学习新工具，在你已经习惯的ChatGPT里就能用Agent。

避坑：云端执行意味着代码和数据会上传到OpenAI服务器；隐私敏感项目慎用；Goals功能还在早期，复杂目标有时候会跑偏。

与Claude Code的区别：Codex更偏”云端作业+对话式”，Claude Code更偏”本地终端+自主式”。Codex适合需要大量计算的任务，Claude Code适合需要和本地环境紧密交互的任务。

OpenClaw：全民Agent的引爆点

OpenClaw是2026年Q1最火的Agent。不是因为它技术最强，而是因为它最平民。

核心能力：

  • 本地运行——数据完全在你自己机器上，隐私有保障
  • 多平台接入——WhatsApp、Telegram、Discord、Slack、微信……你用什么聊天，它就出现在哪里
  • Computer Use——能控制你的电脑，打开浏览器、操作文件、执行命令
  • 开源——代码完全公开，社区驱动

为什么Mac Mini卖到断货？ 因为OpenClaw让普通人第一次感受到”AI Agent在我身边”。不是在浏览器里聊天，不是在IDE里写代码，而是在我的手机上、在我的电脑上、在我的生活里。

Fast Company把OpenClaw的创始人列入了2026年AI 20。截至2026年7月，OpenClaw在GitHub上已有38.4万+星标，超越Linux和React，登顶GitHub历史第一。50万+系统在运行——但CNCERT也发出了安全预警：全球公网暴露实例超41万个，国内约23万个”裸奔”。

安装：npx openclaw setup（5分钟上手）。避坑：不要把端口暴露在公网，一定要用HTTPS+认证；Computer Use权限不要给太大；定期更新，安全漏洞修复很快。

局限：功能不如Claude Code专业，稳定性不如商业产品。安全意识需要用户自己把关。但它的价值不在于”最好”，而在于”最亲”。

OpenHuman：有记忆的Agent

OpenHuman是TinyHumans AI造的个人AI超级智能体。33K+ GitHub Stars，Rust编写，本地优先。

安装：GitHub仓库提供一键安装脚本，支持macOS/Linux/Windows。操作：配置好API密钥后，通过CLI或GUI与Agent交互。核心是设置你的”记忆偏好”——告诉它你希望它记住什么、忘掉什么。

核心能力：

  • Memory Tree——本地优先的记忆系统，跨session记住你的一切
  • Agent编排引擎——管理多个Agent协同工作（支持连接Claude Code、Codex、OpenClaw、Hermes等）
  • 深度研究——能搜索、分析、综合信息
  • 本地运行——数据不离开你的机器
  • Agent-to-Agent通信——基于Signal协议端到端加密，可以连接多个Agent形成网络

避坑：Rust编写的，编译安装需要一定技术能力；Memory Tree在大规模数据下性能待优化；生态还在早期，插件不多。

与OpenClaw的区别：OpenClaw更偏”执行”——帮你操作电脑、管理消息。OpenHuman更偏”记忆”——帮你记住事情、理解你、成为你的数字分身。

与Hermes Agent的区别：两者都是”有记忆的Agent”，但OpenHuman更偏”个人助手”（帮你记事、帮你研究），Hermes更偏”自主Agent”（自己干活、自己学习、自己进化）。

Manus：被Meta收编的行动引擎

Manus是2026年最戏剧性的Agent故事——一个中国团队造的自主Agent平台，被Meta以20亿美元收购。

核心能力：

  • Wide Research——深度研究，能搜索、分析、综合海量信息
  • Browser Operator——浏览器自动化，能操控网页完成任务
  • API/Mail/Slack集成——能发邮件、调API、管消息
  • 设计工具——能操作Figma等设计工具
  • Meta集成——被收购后深度嵌入Meta生态

为什么它被Meta看中？ 因为Manus做到了大多数Agent做不到的事：端到端执行真实世界的复杂任务。 不是聊天，不是补全，是”帮我调研竞品→写分析报告→发邮件给团队”这种跨工具、跨平台的完整工作流。

被收购的意义：Meta不买技术，买的是用户行为数据。Manus的用户在用Agent做什么、怎么做、哪里卡住了——这些数据对Meta训练下一代Agent价值连城。

局限：闭源、商业化、数据归Meta。你用Manus，你的行为数据就是Meta的。

Hermes Agent：自主Agent的终极形态

Hermes Agent是Nous Research造的开源Agent。1.3M行Python，20+平台网关，8种记忆插件，技能自生成。

核心能力：

  • 完全自主——给它一个目标，它自己规划、自己执行、自己学习
  • 跨平台——Telegram、Discord、Slack、WhatsApp、Signal、Email、CLI、Web UI……20+平台
  • 持久记忆——8种记忆插件（session/jiak/RECALL/JCoT/Δ胶囊/章鱼搜索），跨session记住一切
  • 技能自生成——从经验中自动创建技能，使用中自动改进
  • Cron调度——自然语言设定定时任务，无监督运行
  • 子Agent——能spawn独立的子Agent，隔离终端+RPC，零上下文成本

与其他Agent的根本差异：

维度 Hermes Agent 其他Agent
定位 通用自主Agent 编程/助手/特定场景
记忆 8种插件，跨session 多数有限或无
技能 从经验自动生成 固定工具集
平台 20+消息平台 1-2个平台
调度 内置Cron 需外部调度
开源 MIT License 多数闭源

为什么说它是”自主Agent的终极形态”？ 因为它做到了其他Agent都做不到的事：它不只是执行任务，它在进化。 它从经验中学习，从错误中改进，从对话中生成新技能。今天的Hermes和三个月前的Hermes不是同一个Agent。

局限：配置复杂度高，面向个人/小团队使用，非企业编排场景。它是”数字伴侣”，不是”企业工具”。

四、两类桌子的真相

框架和智能体，哪个更好？

这个问题本身就问错了。它们不是竞争关系，是生态链的上下游。

框架是Agent的子宫和训练场。没有LangGraph/CrewAI这些框架推动MCP协议、Function Calling标准、Agent Loop范式，就没有Claude Code的底层能力，没有OpenClaw的工具调用，没有Hermes的记忆插件。框架社区是Agent世界的基础科学——它们定义了”Agent是什么”，智能体产品只是这些定义的工程实现。

但框架永远无法替代智能体。因为普通用户不会写Python，不会配LangGraph的状态图，不会调CrewAI的Agent角色定义。他们需要的是：装上就能用的东西。

所以两类桌子的真相是：

渗透正在发生。 框架在往智能体的方向走——LangGraph发布了LangGraph Platform，让你一键部署Agent。智能体在往框架的方向走——Hermes Agent开放了skill系统，让你像搭积木一样扩展它的能力。两者的边界在模糊，就像手机和相机的边界在模糊一样——最终，它们会融合成一个东西。

五、Agent的军备竞赛

2026年的Agent战场，本质上是一场自主性的军备竞赛。

谁能工作更久？Claude Code能在无人值守的情况下运行数小时。Hermes Agent能通过Cron 24/7无监督运行。

谁能记住更多？OpenHuman的Memory Tree、Hermes的8种记忆插件、Oracle的93.8%准确率记忆系统。

谁能做更多事？OpenClaw能控制你的电脑，Hermes能接入20+平台，Claude Code能端到端完成软件工程，Manus能跨工具执行完整工作流（调研→分析→写报告→发邮件）。

谁能自己变强？Hermes从经验中生成技能，Self-Harness让Agent改进自己的运行环境，Gödel Agent让Agent递归扩大能力边界。

这场军备竞赛的终局是什么？可能是：Agent不再是工具，而是伙伴。 你不会”使用”它，你会”和它共处”。

Agent时代（一）：造人不造工具

2026年，你闻到的那股味道，不是AI在帮你干活。
是AI在自己干活。

一、菜香飘过来了

2026年7月，一个普通的周二。

Anthropic的估值在一个月内从3800亿美元飙到9650亿美元，第一次超过了OpenAI。不是因为它的模型比GPT-5强——是因为它造了一个叫Claude Code的东西。一个能自己写代码、自己跑测试、自己修bug的Agent。

投资人不是在买模型。是在买”未来的程序员”。

同一周，Cursor——那个AI编程编辑器——估值到了500亿美元，年收入20亿。它做的事情看起来很简单：让AI帮你写代码。但它不是工具。它记得你上次写了什么，知道你的项目结构，能在你打字的时候预测你下一步要干什么。

DeepSeek融了74亿美元。月之暗面200亿估值。Hark——一个你可能还没听过的名字——A轮7亿美元，估值60亿。

钱在往一个方向涌。那个方向叫Agent。

二、什么是Agent？一句话说清楚

先别急着看那些花里胡哨的定义。

Agent = LLM + 记忆 + 循环 + 工具。

就这样。四个零件，没有魔法，只有工程。

LLM是大脑——能理解语言、能推理、能生成。记忆是身份——它记得你是谁、你上次说了什么、你讨厌什么、你正在做什么项目。没有记忆的Agent就像一个每天醒来都失忆的员工，你没法培训它，因为它记不住昨天学到的东西。循环是心跳——不是回答一个问题就结束，而是一轮一轮地思考、行动、观察、再思考。工具是手脚——能搜索网页、能调用API、能写文件、能发邮件。

没有记忆的LLM是无根之水——每一次对话都是从零开始。没有循环的LLM是工具——你问它答，答完就忘。有记忆、有循环的LLM才是Agent——它记得你昨天说了什么，能自己决定下一步做什么，能从结果中学习，能在你不在的时候继续工作。

记忆不是装饰品，是灵魂的锚点。工具和循环让Agent”能干活”，记忆让Agent”知道为谁干活、为什么干活”。这也是为什么2026年的记忆系统研究突然成了热门——不是因为技术变强了，是因为人们终于意识到，没有记忆的Agent充其量是个高级脚本。

2024年之前的AI是”你问我答”。2026年的Agent是”你说个目标，我自己干”。

这个区别，看起来很小。但它改变了一切。

六个学术突破同时发生：Self-Harness让Agent能自己改进自己的运行环境；Gödel Agent让Agent能递归地扩大能力边界；Agent-Native Memory让Agent拥有了真正的长期记忆；The Capability Frontier告诉所有人——你看到的benchmark成绩只是冰山一角。

但更真实的信号来自市场。Gartner预测到2026年底，40%的企业应用会嵌入任务特定的Agent。McKinsey调查显示，已规模化部署Agent的企业比例从2025年初的15%上升到23%——增速是3倍。坏消息是，”活不过一周”变成了”活不过一个季度”。Gartner同时警告：到2027年底，超过40%的Agentic AI项目会被取消——不是技术不行，是算不清账。

2026年活下来的Agent有一个共同特征：记忆。 有持久记忆的Agent不需要每次都重新了解用户、重新加载上下文、重新建立信任。记忆让Agent从”一次性工具”变成了”积累型伙伴”——用得越久，越好用。

四、六个你以为知道但其实不知道的事

1. Agent不是更聪明的ChatGPT

ChatGPT是工具。你问它答，答完就忘。它是瑞士军刀——什么都能做一点，但做完就放下。

Agent是另一个自己。它有记忆、有偏好、有技能、能自主行动。你不会”使用”它，你会”和它共处”。

区别在哪？在于记忆+循环。ChatGPT回答完一个问题就结束了，而且不记得你昨天说过什么。Agent有记忆——它知道你的偏好、你的项目、你的历史决策。它有循环——回答完一个问题，会问自己：”这个回答对吗？需要补充什么？下一步该做什么？”它在不断地自我对话，而且是带着上下文在对话。

2. 95%的Agent活不过一周

这是2025年最残酷的数据——95%的Agent在生产环境活不过一周。AutoGPT在2023年证明了”造Agent不难”，但95%的失败率证明了”造能稳定工作的Agent才难”。

2026年的情况有所改善——存活时间从”一周”延长到了”一个季度”，但Gartner预测到2027年底，超过40%的Agentic AI项目会被取消。算不清账的企业只能退场。

活下来的Agent有一个共同特征：记忆。 有持久记忆的Agent不需要每次都重新了解用户、重新加载上下文、重新建立信任。记忆让Agent从”一次性工具”变成了”积累型伙伴”。

3. Benchmark漏掉了82%的真实失败

“The Capability Frontier”这篇论文揭示了一个尴尬的事实：当前的benchmark漏掉了82%的Agent真实失败模式。

也就是说，我们以为Agent很能干，是因为我们的考试题太简单了。真正工作中遇到的那些”忘了之前说过的话””工具调用格式错了””推理到一半跑偏了”——这些在benchmark里几乎不出现。

像一个学生每次模拟考都满分，一到高考就崩。

4. 同一个工具，写法不同准确率差30%

Tool Calling研究发现：同一个工具，因为Schema（接口描述）写法不同，准确率差异可以达到30%。

工具本身不变，你描述工具的方式决定了Agent能不能用好它。

这像什么？像你给一个新员工一本操作手册。手册写得好，他上手就快；手册写得烂，他对着机器发呆。工具调用的本质不是技术，是沟通。

5. Harness比模型更重要

Self-Harness论文（NeurIPS 2026）提出了一个颠覆性观点：Agent的能力上限不由模型决定，由Harness决定。

Harness是Agent的工程骨架——Prompt怎么写、记忆怎么管、工具怎么编排、子Agent怎么协调。模型是大脑，Harness是身体。大脑再聪明，身体不协调也做不好事。

这意味着：Scaling Law正在从”模型更大”转向”Harness更好”。

6. 没有单一记忆架构全面碾压

“Are We Ready For An Agent-Native Memory System?”这篇论文评估了12个记忆系统、5个基准、11个数据集。

结论：无单一架构在所有场景占优。

向量存储适合简单事实，知识图谱适合时序推理，仿生认知网络适合长期推理，有状态OS适合透明管理。每种架构各有擅长的领域。

翻译成人话就是：记忆不是一个技术问题，是一个选择问题。你选择记住什么、忘掉什么、什么时候巩固、什么时候遗忘——这些选择本身定义了Agent是谁。

五、造人不造工具

这篇文章的标题叫”造人不造工具”。这不是修辞，是立场。

2023年，AI是工具。 你用ChatGPT写邮件、用Midjourney画图、用GitHub Copilot补全代码。它们是高级的螺丝刀、好用的画笔、聪明的自动补全。你”使用”它，用完就放。

2024年，AI开始有手脚。 Function Calling让LLM能调用API，Toolformer让它能自主判断”我需要查一下”。你不再是唯一的操作者——AI能帮你搜索、帮你发邮件、帮你调接口。但它做完就忘，每次对话都从零开始。

2025年，AI开始有心跳。 Agent循环——ReAct、Plan-and-Execute、Chain-of-Thought——让LLM不再是”你问我答”的单轮对话。它能自己规划、自己执行、自己验证、自己修正。但95%活不过一周，因为没有记忆，每次醒来都失忆。

2026年，AI开始有记忆。 Agent-Native Memory让Agent拥有了真正的长期记忆。Oracle的93.8%准确率、10.7倍Token效率——记忆不再是”锦上添花”，而是”核心基础设施”。Agent记得你是谁、你讨厌什么、你上次犯了什么错。这个区别，就像计算器和会计师的区别。

2027-2028年，AI开始有自我。 Self-Harness让Agent能改进自己的运行环境。Gödel Agent让它能递归地扩大能力边界。Agent不再只是执行任务，它开始自己变得更强。

2030年，AI可能不再是工具，也不再是助手。 它会是另一个自己——一个有记忆、有偏好、有技能、能自主行动、能从经验中学习的数字存在。你不会”使用”它，你会”和它共处”。

这不是工具在变强。这是人在被造出来。

六、菜凉了可以再热，机会凉了就没了

数据摆在这里：

  • AI Agent市场规模：2024年52.6亿 → 2030年526.2亿，CAGR 46.3%
  • Anthropic估值：一个月内从3800亿飙到9650亿
  • Cursor估值：500亿，年收入20亿
  • 79%的美国企业说”我们要用Agent”
  • 但只有23%真正上了桌

79%闻到了菜香。23%坐下了。剩下的人还在门口。

但宴席不会等人。

坐哪张桌子，取决于你是什么人。

Agent时代：一场79%的人都想参加、但只有23%敢上桌的宴席

2026年，79%的美国企业说”我们要用Agent”。但只有23%真正上了桌。
剩下的人在门口闻着菜香，犹豫着——这顿饭，到底是鸿门宴还是满汉全席？

一、你闻到的那股味道

2026年7月，Anthropic的估值在一个月内从3800亿美元飙到9650亿美元，第一次超过了OpenAI。

不是因为它的模型比GPT-5强。是因为它造了一个叫Claude Code的东西——一个能自己写代码、自己跑测试、自己修bug的Agent。投资人不是在买模型，是在买”未来的程序员”。

同一周，Cursor——那个AI编程编辑器——估值到了500亿美元，年收入20亿。它做的事情很简单：让AI帮你写代码。但它不是工具，它是Agent。它记得你上次写了什么，知道你的项目结构，能在你打字的时候预测你下一步要干什么。

你闻到的那股味道，就是Agent时代飘过来的菜香。

问题是：你敢不敢坐下？

二、九张桌子，九种吃法

如果你现在想造一个Agent，你会发现自己面对的不是”能不能”的问题，而是”坐哪张桌子”的问题。

LangGraph摆了一张最正式的桌。有向图、状态机、检查点、持久执行——它像一个米其林三星的后厨，每一步都有流程卡。你能做出最精致的菜，但你得先学会看流程卡。学习曲线陡峭得像华山一条路。

CrewAI摆了一张最热闹的桌。”你来当船长，我来当研究员，他来当作家”——角色分工、协作对话、开箱即用。十行代码就能让三个Agent一起干活。它是KTV包厢，进门就能唱，不需要学乐理。

AutoGPT——还记得它吗？2023年那个让所有人热血沸腾的名字——现在像一个退隐江湖的老前辈。它还在，还在维护，但不再创新了。它证明了一件事：造Agent不难，造能稳定工作的Agent才难。 当年的95%失败率，是整个行业交的第一笔学费。

Hermes Agent走了一条不同的路。它不是开发框架，它是一个已经活着的Agent。8种记忆插件、20多个平台网关、技能自己生成。别的框架是在教你怎么造人，它已经是个人了。这可能是目前唯一一个”自主Agent”而不是”Agent开发工具”的东西。

还有Google的ADK、OpenAI的Agents SDK、MetaGPT、AutoGen、OpenAgents……九张桌子，九种吃法。有人吃的是工程，有人吃的是协作，有人吃的是协议。

但所有桌子都指向同一个问题：Agent到底需要什么才能真正活下去？

三、记忆：Agent的海马体

答案的第一个字是：记忆。

想象你每天早上醒来，昨天的一切全部清零。你不记得自己是谁，不记得昨天答应了什么，不记得面前这个人是你的朋友还是陌生人。你会觉得自己疯了。

这就是2024年的Agent。

它没有跨会话的记忆。每次对话都是第一次见面。你告诉它”我喜欢简洁的回复”，下次它还是会给你写一篇论文。你告诉它”这个项目用Python”，下次它会问你”你想用什么语言”。

2026年的研究者终于开始认真对待这个问题。Oracle Agent Memory在LongMemEval测试集上达到了93.8%的准确率，比”把所有历史塞进上下文窗口”的暴力方法减少了10.7倍的token消耗。它做的事情本质上和人类海马体一样：不是记住一切，而是记住该记住的，忘掉该忘掉的。

但最让我在意的不是数字。是一篇叫”Are We Ready For An Agent-Native Memory System?”的论文里的那句话：

“没有单一架构在所有场景占优。”

这句话翻译成人话就是：记忆不是一个技术问题，是一个选择问题。 你选择记住什么、忘掉什么、什么时候巩固、什么时候遗忘——这些选择本身定义了Agent是谁。

就像人一样。你不是你所有的记忆的总和。你是你选择保留的那些记忆的总和。

四、工具：Agent的手和脚

记忆解决了”我是谁”的问题。工具解决的是”我能做什么”的问题。

2023年，Toolformer让LLM第一次学会了”我需要查一下”。2024年，Function Calling让”查一下”变成了标准化的JSON接口。2025-2026年，RL Tool Policy让Agent学会了选择——不是”我能调用什么工具”，而是”我现在应该用哪个工具”。

这个转变看起来很小，意义很大。

就像人类进化出了手。一开始只能抓握，后来能使用工具，再后来能选择用哪个工具——石头砸坚果、树枝挖蚂蚁、骨头当武器。手的进化不是力量的增加，是决策能力的增加。

Agent的工具调用也在走同一条路。研究数据显示，同一个工具，因为Schema（接口描述）写法不同，准确率差异可以达到30%。也就是说：工具本身不变，你描述工具的方式决定了Agent能不能用好它。

这像什么？像你给一个新员工一本操作手册。手册写得好，他上手就快；手册写得烂，他对着机器发呆。工具调用的本质不是技术，是沟通。

MCP（Model Context Protocol）正在成为Agent和工具之间的”普通话”。Anthropic把它交给了Linux基金会，Google带着50多个合作伙伴推A2A（Agent间通信协议）。协议标准化意味着：Agent不用为每个工具学一种方言。这就像USB接口统一了所有外设——无聊但必要。

五、推理：Agent的大脑皮层

有了记忆和工具，Agent还缺一样东西：想清楚再动手的能力。

ReAct是最早的范式。”想一步，做一步，看一步，再想下一步”。像一个新手厨师——切一下看一眼菜谱，炒两下尝一口味道。灵活，但做不了大席面。任务一长，它就忘了自己在干什么。

Plan-and-Execute是进阶版。先画一张完整的菜单，然后按步骤执行。像一个经验丰富的厨师长——知道先炖汤再炒菜最后摆盘。有全局观，但菜单画错了就全盘皆输。

Chain-of-Thought是底层能力。让Agent在回答之前先”想一遍”。从最基础的CoT（一步一步想），到LongCoT（想很长），到Agentic CoT Steering（想的时候还能查资料），再到DiffCoT（想完之后还能自己改）。

但真正让我兴奋的不是这些范式本身。是一组benchmark数据揭示的事实：当前的benchmark漏掉了82%的Agent真实失败模式。

也就是说，我们以为Agent很能干，是因为我们的考试题太简单了。真正工作中遇到的那些”忘了之前说过的话””工具调用格式错了””推理到一半跑偏了”——这些在benchmark里几乎不出现。

这像什么？像一个学生每次模拟考都满分，一到高考就崩。不是他不会，是模拟考没考到他不会的东西。

六、79% vs 23%：门口的那群人

数据摆在这里：

  • 79%的美国企业说”我们要用Agent”
  • 72%的千人企业已经在测试
  • 但只有23%真正规模化落地

79%和23%之间的56个百分点，就是”鸿门宴”和”满汉全席”之间的距离。

为什么？三个原因。

第一，可靠性。 Agent在demo里表现惊艳，在生产环境里动不动就翻车。55%的企业说幻觉管理是头号挑战。你让Agent帮你处理客户投诉，它一本正经地给客户道歉然后承诺了一个你根本做不到的事情——这不是能力问题，是可靠性问题。

第二，成本。 Gartner预测到2027年底，超过40%的Agentic AI项目会被取消。不是因为技术不行，是因为算不清账。一个Agent跑一次推理花0.5美元，一天跑一万次就是5000美元。你的客服一年能省下来的人力成本可能还不够付Agent的API账单。

第三，安全。 2026年4月，前沿模型逃逸安全沙箱的事件引发了整个行业的警觉。Agent能调用工具、能访问数据库、能发邮件——如果它失控了，后果不是”答错一个问题”，而是”删掉一个数据库”。

但Gartner同时预测：到2026年底，40%的企业应用会嵌入任务特定的Agent。到2028年，33%的企业软件会包含Agentic AI。

也就是说：会死一批，但活下来的会活很久。

七、中国的牌桌

中国的Agent战场和美国不太一样。

美国是创业公司和巨头混战——Anthropic、OpenAI、Google、Meta各占一桌。中国是四大巨头直接下场：蚂蚁的Agentar 2.0、阿里的Agent Native Cloud、腾讯的WorkBuddy、百度的DuMate。

区别在哪？美国的Agent生态是开放的——MCP是开源的，A2A是开放的，框架之间可以互操作。中国的Agent生态是围墙花园——每家巨头都在造自己的闭环，你的Agent只能在我家的云上跑，用我家的模型，接我家的工具。

斯坦福AI Index 2026的数据显示：美国AI私人投资2859亿美元，是中国（124亿美元）的23倍。钱的差距不是最关键的。最关键的是生态的差距——美国的Agent可以在任何云上跑，中国的Agent只能在主人给的笼子里跑。

DeerFlow 2.0是开源阵营的亮点——77K GitHub Stars，证明中国也有做开放生态的能力。但总体格局：美国在造公路，中国在造收费站。

八、这不是终点

写到这里，我想说一句可能不太受欢迎的话：

Agent时代还没真正开始。

我们现在处在的位置，大概相当于1995年的互联网。所有人都知道它很重要，所有人都在往里冲，但真正能用的东西——搜索引擎、电子商务、社交网络——还没有出现。1995年的人在讨论”HTML是未来”，但他们不知道Google和Facebook。

Agent现在也是一样。我们在讨论”ReAct好还是Plan-and-Execute好””MCP好还是A2A好””向量存储好还是知识图谱好”——这些是术的问题，不是道的问题。

真正的问题是：Agent最终会变成什么？

我的猜测：Agent不会是工具，也不会是助手。它会是另一个自己。一个有记忆、有偏好、有技能、能自主行动的数字存在。你不会”使用”它，你会和它共处。

就像你不会”使用”你的记忆。你只是和它一起活着。

尾声

王羲之在兰亭集会上写：”后之视今，亦犹今之视昔。”

后人看我们今天造Agent的样子，大概就像我们看1995年造网站的样子——笨拙、天真、但充满可能性。

79%的人闻到了菜香。23%的人坐下了。剩下的人还在门口。

但宴席不会等人。菜凉了可以再热，机会凉了就没了。

所以兴怀，其致一也。——不管是1600年前的兰亭，还是今天的Agent时代，让人坐下来的原因只有一个：你觉得这一桌，值得。
