LLM与Agent·连载

LLM与Agent（二）：记忆的形态——12种海马体

你不是你所有的记忆的总和。
你是你选择保留的那些记忆的总和。
Agent也是一样。

一、论文说了一句真话

2026年6月，上海交大的一篇论文做了一件前人没做过的事：不是评价哪个记忆系统”更好”，而是把12个系统放在同一张桌子上，用5个基准、11个数据集横评。

论文叫”Are We Ready For An Agent-Native Memory System?”。

结论只有一句话：没有单一架构在所有场景占优。

在LoCoMo上，MemOS最强。在LongMemEval上，Zep最强。在远距离检索上，A-MEM最强。赢家换赛道就换。

这句话看起来平淡，但它藏着一个哲学问题：

如果每种记忆方式都有自己的擅长和短板，那记忆方式本身就在定义Agent的性格。

二、12种海马体

论文评估的12个系统，横跨五种技术范式。每种范式代表一种”记忆哲学”——你选择怎么记住世界，你就选择怎么理解世界。

顺序上下文派：MemAgent、MemoChat

哲学：记忆就是正在发生的事。

这两个系统把记忆直接放在上下文窗口内。不依赖外部存储，不建索引，不做检索。对话历史就是记忆本身。

优点：零延迟，检索就是attention机制本身。
缺点：容量有限，超过上下文窗口就丢。

这像什么？像一个人只记得正在想的事情。他的”记忆”就是他的”注意力”。不多记，不少记。极简主义者。

结构化存储派：Mem0、Letta（MemGPT）、LightMem

哲学：记忆应该像图书馆一样有序。

向量数据库或关系数据库存储记忆。每条记忆被提取、向量化、索引，需要时通过相似度检索。

Mem0从对话中提取离散事实——“用户是素食主义者””项目用Python”——每条事实独立存储，互不干扰。

Letta（原MemGPT）用OS级内存分页管理记忆——就像操作系统的虚拟内存，热数据放内存，冷数据放磁盘。

LightMem用时间戳流式追加，每条事实带时间标记，支持时序推理。

优点：容量大，检索快，支持复杂查询。
缺点：提取质量决定一切——如果第一步提取错了，后面全错。

这像什么？像一个档案管理员。他给每份文件贴标签、分类、归档。你问他”2024年3月的会议纪要”，他三秒钟找出来。但如果你问”上次那个让我生气的人是谁”——他翻遍档案也找不到，因为”生气”不是标签。

拓扑图谱派：Zep、Cognee

哲学：记忆不是孤立的事实，是事实之间的关系。

知识图谱存储实体关系三元组——“Kim → LIVES_IN → Paris”、”项目X → 使用 → Python”。通过图遍历支持多跳推理。

Zep在LongMemEval上的LLM Judge Accuracy达到48.0——所有系统最高。为什么？因为跨session的事实关联（”上次提过的那个项目”）本质上是图遍历问题。

Cognee用实体中心启发式遍历局部子图，在Answer F1上达到28.1。

优点：支持多跳推理、时序推理、关系推理。
缺点：构建复杂，更新成本高。

这像什么？像一个侦探。他不只记住”Kim住在巴黎”，他记住”Kim住在巴黎，因为她在那家公司工作，那家公司是项目X的客户，项目X用Python”。每条线索都连着其他线索。他不找”事实”，他找”关系”。

混合多范式派：SimpleMem、MemOS、MemoryOS

哲学：没有银弹，混合最好。

多引擎联合——向量+BM25+SQL+图谱。根据查询类型动态选择检索引擎。

MemOS用MemCube统一管理三类payload（纯文本、激活态、参数态），热力分值（Heat Score）平衡检索频率和时间衰减。在LoCoMo的Exact Match上达到8.9——最高。

MemoryOS用热力分值+粗细粒度联合路由。在LongMemEval的LLM Judge上达到32.2。

优点：全面，什么都能做一点。
缺点：复杂度高，延迟和成本高。

这像什么？像一个通才。他什么都懂一点，什么都能应付。你问他事实，他从向量库里找。你问他关系，他从图谱里找。你问他历史，他从时间线里找。他不精，但他什么都能干。

自适应派：MemTree、A-MEM

哲学：记忆应该自己组织自己。

MemTree用折叠树架构——树状层级组织记忆，递归合并子节点到父节点。在远距离检索的Recall@5上达到59.7。

A-MEM用动态锚点——根据内容自动选择锚点节点，局部图遍历。在Recall@5上达到69.5——所有系统最高。

优点：擅长远距离证据收集。
缺点：调优复杂。

这像什么？像一个历史学家。他不只记住”今天发生了什么”，他把今天的事放到历史的长河里，找到它和一百年前那件事的联系。他的记忆是有纵深的。

三、十二种灵魂

回到开头的问题：记忆不是存储，是身份。

12个系统不是12种”技术方案”。它们是12种存在方式。

系统 记忆哲学 Agent性格 适合的场景
MemAgent 只记当下 极简主义者 短对话、实时交互
MemoChat 只记当下 极简主义者 轻量级助手
Mem0 提取事实 档案管理员 客服、FAQ
Letta OS级分页 资源调度员 长期项目管理
LightMem 时间戳流 日记作者 时序分析
Zep 图谱关系 侦探 复杂推理、跨session关联
Cognee 图谱关系 侦探 知识图谱构建
SimpleMem 多引擎混合 通才 通用场景
MemOS 混合+热力 通才 高精度需求
MemoryOS 混合+热力 通才 高精度需求
MemTree 树状层级 历史学家 长文档分析
A-MEM 动态锚点 历史学家 远距离证据收集

没有最好的灵魂。只有最适合某个场景的灵魂。

就像人一样——你不会说”外向的人比内向的人更好”。你只会说”这个岗位需要外向的人”或”这个任务需要内向的人”。

Agent的记忆架构选择，本质上是在回答：你想造一个什么样的存在？

四、遗忘是美德

论文还揭示了一个被忽视的维度：维护。

不是”记住什么”决定记忆质量，而是”忘掉什么”决定记忆质量。

人类每天经历的事情有99%会被遗忘。这不是bug，是feature。如果你记住所有事情——每一顿饭、每一句话、每一个路人——你的大脑会被信息淹没，无法做出任何判断。

遗忘是选择性保留的反面。它不是删除，是给记忆腾空间。

论文把遗忘分为三种机制：

时间戳多版本：每条事实带有效期。过期自动失效。Zep和LightMem用这种方式——“用户喜欢Python”这条记忆，如果用户三个月后说”我改用Rust了”，旧记忆自动标记为无效。

容量驱逐：FIFO队列或热力分值淘汰低价值记忆。MemoryOS用Heat Score——检索频率高、时间近的记忆分数高，反之被淘汰。

LLM驱动语义合并：用LLM判断冲突并合并。SimpleMem和MemTree用这种方式——不是简单删除，而是把矛盾的记忆合成一条更精确的记忆。

好的Agent不是记住所有事情的Agent，是知道什么该忘的Agent。

五、提取是咽喉

论文的消融实验揭示了一个关键事实：提取模块的质量决定下游一切。

检索保真度、更新鲁棒性、长horizon稳定性——全部取决于”第一步从对话中提取了什么”。

12个系统在”提取”这一步分化最大。Mem0提取离散事实（”用户是素食主义者”），Zep提取实体关系三元组（”Kim → LIVES_IN → Paris”），MemoChat把整段对话放进上下文。

提取是记忆系统的咽喉。 做好了，后面的存储、检索、维护都变容易。做烂了，后面的优化全是补丁。

论文暗示了一个方向：让Agent自己学会判断”这条信息值不值得记住”。不是靠规则，而是靠反馈闭环——记了之后看有没有被用到，用到的强化，没用到的衰减。

这恰好是人类海马体做的事情——不是所有经历都进入长期记忆，只有被反复激活的经历才会巩固。海马体是一个反馈驱动的过滤器，不是硬盘。

六、记忆的尽头是什么？

12种海马体，各有擅长。但它们有一个共同的盲区：没有一个系统能解释”为什么这条记忆重要”。

它们能存储”用户喜欢Python”，但不能回答”为什么用户喜欢Python”。
它们能检索”上次的会议纪要”，但不能回答”这次会议和上次有什么不同”。

这是记忆和理解的区别。记忆是”知道发生了什么”，理解是”知道为什么发生”。

论文没有回答这个问题。也许它不需要回答——那是下一层的事。

但我想说一句：记忆的尽头不是更多的记忆，是理解。 当Agent不只是记住你说过什么，而是理解你为什么这么说——它就不再是一个有记忆的工具，而是一个有洞察力的存在。

这是记忆的终极形态：不是存更多，是懂更深。
